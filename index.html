About

A little about me

I'm a software engineer focused on identity, security, and cloud infrastructure — the systems other teams build on top of and rarely have to think about. For the past four years at Trellix (formerly McAfee), I've helped build and run the IAM platform behind every Trellix product, handling 110,000+ sign-ins a day across commercial AWS and FedRAMP-regulated GovCloud.

I gravitate toward deep ownership of critical systems. I'm the sole maintainer of our Keycloak identity server — ten-plus major upgrades with zero downtime — and I lead our FedRAMP/GovCloud IAM work end to end, from features and compliance (Moderate, High, DoD IL5) through incident response. Along the way I've built our first edge rate-limiting layer, closed out 60+ security-scan findings, and kept our cryptography FIPS 140-2/140-3 compliant.

Most recently I've been leaning into AI-assisted platform engineering — building tooling that compresses multi-hour, error-prone upgrades into five-minute automated runs, and turning a projected multi-year service rewrite into a two-month one. I care about the unglamorous engineering that keeps important systems secure, reliable, and pleasant to build on.

Outside of work you'll find me in the Seattle area cheering (and often suffering) for the Mariners, Seahawks, and Blazers. Go Mariners. 🐟

Things I've built

Professional work

Platform & identity engineering at Trellix

OAuth Implicit → Auth Code + PKCE Migration

2023–24

Led a platform-wide migration from the legacy OAuth Implicit flow to Authorization Code Flow with PKCE, coordinating changes across four separate repositories — the Keycloak server, the Node.js Lambda backend, the browser sign-in SDK, and the FedRAMP environment. PKCE is now the default authentication flow for every Trellix product, hardening 110k+ daily authentications against token-interception attacks. Along the way I cut sign-in load by ~20% by removing a blocking, multi-second /scopes fetch that gated the login form, moving scope resolution to a cached backend authorization service.

Node.jsOAuth 2.0KeycloakJavaScript

SAML IdP Delegation Service

2026

Designed and built a reusable SAML Identity Provider service that lets Trellix act as a SAML IdP on top of its existing OAuth/OIDC identity: it ingests a Trellix IAM token, parses the claims, and mints a signed SAML assertion, while exposing a signing-certificate metadata API so downstream Service Providers can verify those signatures. It directly unblocked the sale of Trellix's Mobile Threat Defense product, which couldn't ship without IAM-token→SAML support — and because it's generic, any future SAML-only product now onboards with zero custom integration work.

Node.jsAWS LambdaSecrets ManagerSAML 2.0

Client Credentials Management Dashboard

2022–23

Built a full-stack OAuth 2.0 machine-to-machine credential management system end to end, including the entire backend Lambda API and its integration with the admin UI. It replaced a slow, ticket-driven IAM provisioning process with on-demand self-service, letting teams create and manage their own client credentials directly — which cut manual client-creation requests to zero and removed a recurring bottleneck for the IAM team.

Node.jsAWS LambdaRDSAngularJS

Keycloak FIPS 140-2 Prototype

2021–22

Prototyped FIPS 140-2 compliance for Keycloak by wiring BouncyCastle FIPS cryptographic providers in at the JVM level — a prerequisite for running the identity platform in FedRAMP and DoD environments. The work was contributed back upstream and cited in the official Keycloak release notes, and it laid the cryptographic groundwork for the FedRAMP/GovCloud platform I maintain today.
